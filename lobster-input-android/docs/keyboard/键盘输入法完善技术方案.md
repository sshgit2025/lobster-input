# 打字键盘(中文拼音输入法)完善技术方案

> 适用范围:lobster-input-android + lobster-input-ios 的「打字键盘」模式(26 键全拼 + 9 宫格 T9)。两端镜像同一套架构与方案。
> 版本:v1.0(评审稿) · 日期:2026-06-26
> 作者视角:业务架构师 / 输入法工程
>
> **范围边界(硬约束)**:本方案 **只涉及键盘模式(Typing)**。**严禁改动语音模式(Voice)的业务代码与数据链路**——包括语音历史、指令二次加工、SYNC/REALTIME 设置开关、`commitRealtimeFinalText` 等语音权威提交路径。键盘内麦克风可以**复用** voice 的底层 streamer/WS 与平滑组件,但其上层业务保持「数据隔离」(不写语音历史、不参与指令加工)。

---

## 0. 一句话结论

当前键盘已具备「中文拼音可用形态」(26 键全拼 + 9 宫格 T9 + 整句 + 简拼 + 调频 + 用户 bigram 联想),但属于 **半成品**:对标成熟输入法缺口集中在 ① 引擎容错能力(模糊音 / 纠错 / 云输入 / 语言模型) ② 高频交互(候选翻页 = 死代码、9 宫格编号选词 = 摆设、光标移动 / 智能标点全缺) ③ 产品闭环(emoji / 剪贴板 / 双拼 / 隐私纯净键盘) ④ iOS appex 内存风险(词库 ~15MB 急加载)。键盘内麦克风的实时 ASR 平滑 **已天然复用语音模式的 `TypewriterReveal`,无需重抄**,但存在两个收尾一致性缺陷需修。

| 候选分层排序 | ✅ | ✅ | 整句>全拼精确>简拼精确>前缀联想>单字兜底 |

| 中英切换 / Shift 三态 | ✅ | ✅ | |
| 符号页 / 数字长按 | ✅ | ✅ | |

| 撤销上屏 | ✅ | ✅ | `TypingUndoManager` |

### 1.2 半成品 / 缺陷(本次重点修复)
**死代码 / 摆设(高优先,小成本)**
- **候选翻页是假的**:`scrollOffset` 字段恒为 0,从不自增;「展开」只是放开单行横向滚动,没有真正分页、没有多行候选面板。(两端)
- **9 宫格编号选词是摆设**:候选显示 `1.词` 编号,但**没有任何数字键去按编号选词**,纯文案;且条件判断对 T9 恒真,打字全程显示却不可用。(两端)
- **iOS `rememberTypingMode` 是死设置**:只读不写、无 UI 开关,等价恒 false → **每次切换输入框 / 选区变化都强制退回语音面板**,严重干扰连续打字。(iOS 专项)

**引擎能力缺失**
- 无模糊音(zh/z、ch/c、sh/s、l/n、an/ang、in/ing…),方言用户掉候选。
- 无容错纠错(打错一个字母直接无候选,如 `nihap`)。
- 无双拼(业界 P0,微信/搜狗标配 ≥4 方案)。
- 整句切分**无 N-gram 语言模型**,仅「最少词数 + 词频」DP,长句易碎切;冷启动联想基本为空。
- 无云输入 / 在线候选,长尾词、新词命中受静态词库限制。
- T9 DFS 展开有硬上限(512/120),且为修历史卡死打了一堆补丁(`MAX_T9_SEG`、`maxL=9`),病态串仍是性能热点。

**交互缺失**
- 无光标移动(方向键 / 空格滑动移光标 / 编辑面板)—— 编辑长文本困难。
- 无智能标点(括号引号自动配对、中英标点上下文自适应)。
- 26 键主面板缺独立句号「。」键。
- 无滑行输入(glide typing,26 键)。
- 无候选长按删用户词 / 用户词条管理 UI(误学的词无法清除)。
- 删除键无「整词删」,仅逐字符。

**产品闭环缺失**
- 无 emoji / 颜文字面板,无 emoji 联想。
- 无剪贴板历史。
- 无快捷短语。
- 无键盘设置入口(高度 / 单手 / 主题 / 反馈可配)。
- **无密码框纯净键盘 / 隐私处理(P0 合规)**:`isPasswordField` 有定义但未据此禁用 composing 预览与麦克风,存在密码框下下划线预览 / 语音上屏的合规隐患。

**性能 / 工程**
- iOS appex 内存:词库稳态 ~14.7MB(`[UInt8]` 全量拷贝 + 三个 `[Int]` 索引),**急加载**(纯语音用户从不进键盘也常驻);叠加保温麦克风 + 录音缓冲,中低端机逼近 jetsam 上限。
- 安卓用户词典用 SharedPreferences 拼大字符串全量序列化,量大刷盘开销与丢失风险高。
- 词库加载期整盘 blockOverlay 阻塞输入;加载失败无重试入口。

### 1.3 对标差距矩阵(P0/P1/P2)
> 基线来自搜狗 / 百度 / 讯飞 / 微信键盘 / 华为小艺产品文档 + rime-ice / FlorisBoard / OpenBoard 开源实现。

**P0 必备(不做即「不合格」/ 影响可用性与合规)**
- 引擎:模糊音(可逐项开关,≥9 组)、容错纠错(键位临近)、隔音符分词键(已有 `'`)、词频调频(已有)、用户自造词(已有)。
- 交互:**真候选翻页(左右滑 / 上滑多行面板)**、**9 宫格数字键编号选词**、空格上屏首选(已有)、空格滑动移光标、26↔9 切换不丢拼音串(已有)。
- 产品:中文符号面板(已有)、**智能标点(配对 + 中英自适应)**、中英混输、**emoji 面板**、**密码框纯净键盘 / 隐私禁学习禁云**、iOS Full Access 不开也能用基础功能。
- iOS:修 `rememberTypingMode` 死设置;词库内存治理(否则撞墙)。

**P1 重要(决定「好不好用」)**
- 引擎:云输入(带隐私开关)、整句纠错进阶、emoji 联想、双拼(≥4 方案)。
- 交互:上滑多行候选面板、长按键选符号、按键气泡预览(已部分)、撤销自动纠错、独立编辑面板(方向 / 复制粘贴)、长按候选删用户词、删除键整词删。
- 产品:快捷短语、颜文字、最近 emoji、数字 / 金额 / 日期智能上屏、剪贴板管理、无痕模式。
- T9:左滑删词、手动分词纠正、整句模型重排。

**P2 增强(差异化)**
- 神经语言模型云端重排、滑行输入、辅码 / 拆字反查、翻译、键盘内 AI 改写润色(结合本产品 AI)、主题市场、浮动键盘。

## 2. 键盘内麦克风 · 实时 ASR 平滑评估(用户核心问题)

### 2.1 结论:无需重抄,已天然复用;但需修两个收尾缺陷
本周语音模式优化的实时 ASR 平滑(安卓 `4374962` / iOS `e8b81b7`)核心是新增 **`TypewriterReveal`**(把火山 Seed-ASR 突发到达的中间结果——~390ms 跳 2 字 + 偶发 1s 停顿——转成稳定逐字揭示,自适应速率)。

- **安卓**:语音模式与键盘麦克风(`KeyboardRealtimeMic`)**各持一个 `TypewriterReveal` 实例,平滑策略完全一致**。键盘麦克风 `preview()` → `typewriter.setTarget()` → `renderComposing()` → `ic.setComposingText()`,**已是逐字打字机平滑而非整段替换**。
- **iOS**:`replaceRealtimePreview` 的 guard 是 `realtimeRecognitionEnabled || isTypingMicActive`,**键盘麦克风路径同样走 `realtimeTypewriter`**,预览逐字平滑,与语音模式共用同一套。

→ **所以「键盘小麦克风」已经天然适配了语音模式刚优化的平滑策略,不需要把策略再抄一遍。** 这是模块化复用的正确结果。

### 2.2 但有两个不对称缺陷(本次一并修,属键盘域,不动语音)
1. **iOS 键盘麦克风收尾缺 `flush()`**:语音模式 `endRealtimeRecording` 会 `realtimeTypewriter.flush()` 把预览补齐;键盘麦克风的 `endKeyboardMicCapture` / `finishTypingMic` **没调 flush**,停手瞬间打字机 timer 可能仍在 tick,预览停在揭示一半的状态(最终结果正确,但视觉「长字」)。
   - 修法:`finishTypingMic` 提交前先 `realtimeTypewriter.flush()`(或在键盘麦克风停止路径补一次 flush)。仅动键盘路径。
2. **安卓键盘麦克风最终文本靠 `delay(900ms)` 后 `finishComposingText` 定格**:若 `onCompleted` 在 900ms 后到达,尾部更正会丢;时序竞态。
   - 修法:改为「`onCompleted` 到达即 flush + finish」与「超时兜底」二者竞速,以先到者定格,移除固定 900ms 盲等。仅动 `KeyboardRealtimeMic`。

### 2.3 键盘麦克风与语音模式的「业务落差」(设计取舍,本次不强求拉平)
键盘麦克风为「数据隔离」刻意**不走** voice 的权威最终文本路径(`requestRealtimeText` / `commitRealtimeFinalText`),因此缺:后端二次加工、指令处理、智能标点 / 数字规整、热词替换、写历史。
- **决策建议**:保持隔离原则不变(符合既有架构),但可把「**智能标点 / 数字规整**」做成键盘域的**本地轻量后处理**(见 §3.3 智能标点模块),让键盘麦克风上屏文本也享受标点规整,而不触碰语音业务代码。是否引入需评审拍板。

## 3. 技术方案(分层 · 两端镜像)

> 总原则:① 两端**同构对称**(算法 / 交互行为一致,各自语言实现);② **引擎层与视图层解耦**,新能力优先做在 `PinyinEngine` / `PinyinDictionary`,视图只消费;③ 所有新功能**带开关**,默认值对齐业界;④ **不触碰语音模式文件**,键盘域改动集中在 `keyboard/` 子树。

### 3.1 引擎层(`PinyinEngine` / `PinyinDictionary` / `UserDictionary`)

**(A) 模糊音 [P0]**
- 在 `PinyinDictionary` 的音节匹配层引入「模糊音派生」:把用户输入的音节按开关派生出等价音节集合参与查词(对齐 rime-ice `derive` 思路)。
- 配对(默认全关,用户逐项开):声母 `z/zh`、`c/ch`、`s/sh`、`l/n`、`f/h`、`r/l`;韵母 `an/ang`、`en/eng`、`in/ing`、`ian/iang`、`uan/uang`。
- 9 宫格因字母已合并,模糊音收益更大,优先保证 T9 路径生效。
- 候选对模糊命中**降权**(精确 > 模糊),避免污染首选。

**(B) 容错纠错 [P0 基础 / P1 进阶]**
- 基础:键位临近纠错(相邻键误触)+ 常见拼写错(`v/ü/u`、`ing/ign` 颠倒、漏韵),用编辑距离(≤1)生成候选并**强降权**,仅在精确候选不足时补位。
- 进阶(P1):整句盲打的多错音纠正,依赖语言模型重排。

**(C) 整句语言模型升级 [P1]**
- 现状 DP 只用「最少词数 + 词频」,长句碎切。引入**本地 bigram 语言模型**(词→词转移概率)做整句重排,Viterbi 解码。
- 数据来源:① 离线从 rime-ice / 开放语料预统计一份**小型内置 bigram**(几 MB,压缩存储),解决冷启动「联想为空」;② 叠加用户 bigram 自学习(已有)。
- iOS 内存敏感:bigram 表用紧凑二进制 + mmap(见 §3.4),或仅在云输入开启时走云端重排。

**(D) 云输入 / 在线候选 [P1]**
- 联网时请求云端整句 / 长尾候选,候选加「云」角标,与本地候选融合排序。
- **隐私硬约束**:密码框 / 无痕模式 / 用户关闭时**禁用云输入**。
- 复用现有后端网络栈,新增键盘域云候选接口(不复用语音接口)。

**(E) 双拼 [P1]**
- 内置主流方案:自然码、小鹤、微软、搜狗(+ 智能 ABC / 拼音加加 / 紫光,对齐微信 7 种)。
- 在输入策略层加「双拼解析器」:2 键 → 1 音节,复用现有词库;支持双拼 + 模糊音 + 纠错叠加。
- 设置页加方案选择 + 键位图。

**(F) 联想增强 [P1]**
- bigram 联想从 1 阶可选扩到结合内置 bigram(冷启动可用)。
- emoji 联想:词→emoji 映射小表(开心→😄、爱你→❤️),候选区融合。
- 修 `lastWord` 易断链问题:空格 / 标点上屏不应清空联想上下文,仅切换输入框 / 显式取消才清。

### 3.2 交互层(`KeyboardController` / `CandidateBarView` / `InputStrategy`)

**(A) 真候选翻页 + 多行候选面板 [P0]** —— 修死代码
- 候选条:左右滑分页(实现 `scrollOffset` 真正自增 / 分页),页码记忆。
- 右侧下拉箭头:展开**多行网格全候选面板**(找生僻词),覆盖键盘区,可滚动,点选即收起。
- 两端 `CandidateBarView` 统一行为。

**(B) 9 宫格数字键编号选词 [P0]** —— 修摆设
- T9 候选编号 `1–9` 与数字键 / 候选点击对应:按编号键直接选对应候选(或保留点选 + 编号键双通道)。
- 明确编号显示条件(仅 T9 中文、有候选时),去掉恒真摆设逻辑。

**(C) 光标移动 [P0/P1]**
- P0:**空格键左右滑动移光标**(Gboard 方案,高频)。
- P1:独立编辑面板(方向键 / 全选 / 复制 / 剪切 / 粘贴),对齐华为小艺 / 搜狗。

**(D) 删除增强 [P1]**
- 删除键长按连删(已有)+ 整词删(composing 内整词回退 / 已上屏按词删)。
- T9 删除键左滑整词删。

**(E) 滑行输入 glide typing [P2,26 键]**
- 轨迹点序列 → 拼音 → 候选 + 语言模型。技术较重,排后期。

**(F) 用户词管理 [P1]**
- 长按候选 → 删除该用户词 / 取消调频;设置内词库管理页(增删改、导入导出)。

### 3.3 产品层(闭环必需)

**(A) 智能标点 [P0]**
- 括号 / 引号自动配对(输 `(` 补 `)`,中文 `「」""`,光标居中)。
- 中英标点上下文自适应:中文模式全角 `,。`,英文 / 数字上下文半角 `,.`。
- 连续标点、句末标点智能。
- 模块:键盘域 `SmartPunctuation`,亦可供键盘麦克风上屏文本做后处理(见 §2.3)。

**(B) emoji / 颜文字面板 [P0/P1]**
- emoji 分类面板 + 搜索 + 最近使用 + 肤色;颜文字面板(P1)。
- iOS 注意资源体积与内存(emoji 走系统字体,不额外打包大图)。

**(C) 26 键独立句号键 [P0,小成本]**
- 主面板补「。」/`,` 高频中文标点,减少绕路。

**(D) 剪贴板历史 [P1]**
- 多条历史、置顶、自动清理、隐私保护(密码 / 无痕不记录)。

**(E) 快捷短语 [P1]** —— 口令→长文本(邮箱 / 地址 / 客套话)。

**(F) 数字 / 金额 / 日期智能上屏 [P1]** —— `v模式` / 人民币大写 / 日期格式。

**(G) 键盘设置入口 [P1]** —— 高度 / 单手(左右浮动)/ 主题 / 震动声音可关 / 气泡预览开关。

**(H) 隐私与合规 [P0]**
- **密码框纯净键盘**:`isPasswordField` 时禁用 composing 预览、禁用麦克风上屏、禁用云输入、禁用学习 / 联想 / 剪贴板。两端按 `EditorInfo.inputType` / `textContentType` 判定。
- 无痕 / 隐私模式开关(不写词库)。
- iOS:不开 Full Access 也能用基础打字(审核 + 信任关键),Full Access 说明文案到位。

### 3.4 性能 / 内存治理(iOS 为主,P0)

**iOS appex(撞墙风险,增功能前必做)**
- 词库改 **懒加载**:首次进入打字模式才 `loadAsync`,纯语音用户零词库占用;可考虑退出打字模式后卸载。
- `[UInt8]` 全量拷贝 → **`Data(contentsOf:options:.mappedIfSafe)` mmap**,内核按需分页,消除加载峰值翻倍,常驻 RSS 大降。
- 三个 `[Int]` 索引 → 紧凑类型(行偏移 `[UInt32]`、key 长度 `[UInt16]`),~6MB 降至 ~2.3MB。
- 评估**合并 / 派生 `initials_dict`**(简拼运行时由全拼派生),省掉 ~4MB 第二张表。
- 修 `PinyinEngine.loading` 标志线程安全(后台写主线程读的数据竞争)。
- 录音中 `CADisplayLink` 波形持续重绘,叠加录音引擎需关注;非录音态停 link。

**安卓**
- 用户词典 SharedPreferences 大字符串 → SQLite / Room 或文件 KV,增量持久化,降丢失风险。
- 词库加载期 blockOverlay → 改非阻塞 + 进度提示;加载失败加**重试入口**(去掉永久 block)。

### 3.5 键盘麦克风收尾修复(§2.2 落地)
- iOS:`finishTypingMic` 提交前 `realtimeTypewriter.flush()`。
- 安卓:`KeyboardRealtimeMic` 移除 900ms 盲等,改 `onCompleted`-or-timeout 竞速 flush+finish。
- 可选(评审定):键盘麦克风上屏文本接 `SmartPunctuation` 本地后处理(不碰语音业务)。

## 4. 工程落地与两端一致性

### 4.1 改动收敛在键盘域(保护语音模式)
- 安卓:仅 `app/.../keyboard/` 子树(`pinyin/`、`typing/`、`KeyboardRealtimeMic.kt`、`TypewriterReveal.kt` 复用);**不动** `LobsterIME.kt` 中语音模式的 `realtimeTypewriter` / `commitRealtimeFinalText` 等 2039–2127 段语音提交逻辑。
- iOS:仅 `LobsterKeyboard/Pinyin/`、`LobsterKeyboard/Typing/`;`KeyboardViewController.swift` 只改键盘麦克风分支(`finishTypingMic`),**不动** `commitRealtimeFinalText` / `endRealtimeRecording` 语音权威路径。
- 所有新增设置项走键盘域 Preferences,避免污染语音设置。

### 4.2 两端对称交付
- 每个引擎能力(模糊音 / 纠错 / bigram / 双拼)先定**统一算法规格 + 测试用例集**(case 体系,对齐已有提示词回归思路),两端各自实现并跑同一组 case 对拍,保证候选一致。
- 词库 / bigram / emoji 映射等数据文件**两端复用同一份**(安卓 `assets/`,iOS `Resources/`),生成脚本统一放 `docs/pinyin-dict/`。
- rime-ice 许可合规:正式上线前确认(已在 memory 标记)。

### 4.3 风险
- 引擎升级回归:模糊音 / 纠错可能污染首选,必须有候选对拍回归集。
- iOS 内存:bigram / 云缓存增量必须配合 §3.4 内存治理,否则 jetsam。
- 双拼 / 滑行成本高,排后期,避免阻塞 P0。

## 5. 迭代排期建议(评审后细化)

**M1 — 修半成品 + P0 合规(1~1.5 周,高性价比)**
- 真候选翻页 + 多行面板;9 宫格编号选词;26 键句号键。
- 智能标点(配对 + 中英自适应);空格滑动移光标。
- 密码框纯净键盘 + 隐私禁用链;iOS `rememberTypingMode` 死设置修复。
- iOS 词库懒加载 + mmap + 索引瘦身(内存先止血)。
- 键盘麦克风收尾修复(iOS flush / 安卓竞速)。

**M2 — 引擎容错 + emoji(1.5~2 周)**
- 模糊音(逐项开关)+ 基础容错纠错。
- emoji 面板 + emoji 联想;最近 emoji。
- 用户词管理(长按删词);删除整词。
- 安卓用户词典持久化迁移。

**M3 — 体验进阶(2~3 周)**
- 本地 bigram 语言模型(内置 + 用户)整句重排;联想增强。
- 云输入(带隐私开关);剪贴板历史;快捷短语;数字/日期智能上屏。
- 编辑面板(方向/复制粘贴);键盘设置入口(高度/单手/主题/反馈)。

**M4 — 差异化(排期待定)**
- 双拼(≥4 方案);滑行输入;键盘内 AI 改写润色(结合本产品 AI);翻译。
